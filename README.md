# Git Sync (Unity 커밋·푸시 도구)

Unity 안에서 **고른 파일만 로컬 커밋**하고, **정해진 시간마다 묶음 커밋 1개로 푸시**하는 도구입니다.
커밋 설명은 형식이 정해져 있어 기록이 한눈에 보입니다.

```
2026-11-11 PM 5:24

작업 내용
- 스크립트 2개 수정: PlayerController, UnitGenerator / 씬 Village 수정

파일: 추가 1, 수정 2
총 작업한 내용: 3개
```

운영 규칙은 [`Documentation~/Git 운영 가이드.md`](Documentation~/Git%20운영%20가이드.md)에 있습니다.
이 문서의 `MyGame`은 예시 프로젝트 이름입니다. 자기 프로젝트 이름으로 바꿔 읽으세요.

## 1. 처음 시작하기

### 1-1. 필요한 것
| 프로그램 | 버전 | 비고 |
|---|---|---|
| Unity | 2021.3 이상 | |
| Git | 2.25 이상 | 명령줄 `git`. 없으면 Git Sync 패널의 **[Git 설치]** 버튼으로 설치 |
| Python | 3.8 이상 | 표준 라이브러리만 씀. 없으면 패널의 **[Python 설치]** 버튼으로 설치 |
| Claude Code (`claude`) | — | 선택. 작업 내용 자동 요약을 쓸 때만 |

### 1-2. 설치
Unity에서 **Window → Package Manager → 왼쪽 위 + → Add package from git URL…** 에 넣습니다.

```
https://github.com/KimJunKi1024/UnityGitSync.git
```

- 버전을 고정하려면 끝에 태그를 붙입니다. 예: `https://github.com/KimJunKi1024/UnityGitSync.git#v1.6.0`
- `Packages/manifest.json`의 `dependencies`에 직접 넣어도 됩니다.
  ```json
  "com.teamelarin.gitsync": "https://github.com/KimJunKi1024/UnityGitSync.git"
  ```
- 저장소가 비공개(Private)이면 설치하는 PC에 GitHub 로그인(Git 자격 증명)이 되어 있어야 합니다.

### 1-3. Git Sync 패널로 확인
**Tools → Git → Git Sync 패널**을 열어 모든 항목이 ✔인지 봅니다. 패키지를 처음 설치하거나 업데이트하면 에디터를 켤 때 한 번 자동으로 뜹니다.
✖가 있으면 그 줄의 버튼이나 안내대로 해결하고 **다시 확인**을 누릅니다. 자세한 내용은 [Git Sync 패널](#git-sync-패널)을 보세요.

### 1-4. 설정 확인
**Tools → Git → 설정**을 엽니다.

- **팀원**: 프로젝트를 만든 사람이 정해 둔 값이 Git으로 함께 내려오므로 **아무것도 바꾸지 않습니다.** 각 칸 아래 `이 PC에서 확인` 줄이 모두 ✔이면 끝입니다.
- **처음 프로젝트를 만드는 사람**: **자동으로 채우기**를 누르고, 값을 확인한 뒤 **저장**합니다. 그다음 `ProjectSettings/GitSyncSettings.json`을 커밋하면 팀 모두가 같은 값을 씁니다.

칸마다 무엇을 적는지는 [설정](#설정)을 보세요.

## 2. 매일 쓰는 법

모두 **Tools → Git → 커밋 창**에서 합니다.

| 언제 | 할 일 |
|---|---|
| 작업을 시작할 때 | 아래쪽 **카운트 시작** (푸시 시간을 이때부터 셈) |
| 작업 하나가 끝났을 때 | 바뀐 파일 중 그 작업 파일만 체크하고 커밋 |
| 푸시 차례가 됐을 때 (기본 60분) | **푸시…** → 미리보기를 확인하고 푸시 |

- 푸시 시간은 푸시한 순간이 아니라, 푸시한 뒤 **다음 작업을 시작한 순간**(카운트 시작)부터 셉니다.
- 푸시 차례에 작업 중이면 그 작업을 끝낸 뒤 푸시합니다.
- 여러 PC나 여러 사람이 작업하면, 작업 전에 GitHub Desktop에서 **Pull**로 먼저 받습니다.

## 3. 화면별 설명

### Git Sync 패널
**Tools → Git → Git Sync 패널**

- 패키지 버전과 함께 두 묶음을 실제로 실행해 ✔/✖로 보여 줍니다.
  - **필요한 프로그램**: git 2.25 이상, Python 3.8 이상, claude(선택)
  - **이 프로젝트**: 도구, Git 저장소, 설정 파일, 원격과 지금 브랜치
- 빠진 프로그램에는 **[Git 설치]·[Python 설치]** 버튼이 있습니다.
  - Windows에서 winget이 있으면 확인 후 새 창에서 설치합니다. 없거나 macOS면 다운로드 페이지를 엽니다.
  - 표준 위치에 설치하면 Unity를 다시 켜지 않고 **다시 확인**만 눌러도 찾습니다.
- 표시 색:
  - **빨강**: 커밋에 필요. 빠져 있으면 커밋 창·커밋·푸시를 쓸 수 없고, 누르면 이 패널이 대신 뜹니다.
  - **주황**: 푸시에만 필요하거나 선택 항목. 원격이 없거나 첫 커밋 전인 새 저장소, 다른 브랜치에 있을 때도 로컬 커밋은 할 수 있습니다.
- 툴바에 **업데이트 확인** 버튼, 아래쪽에 커밋 창·설정·사용법·운영 가이드·변경 기록·GitHub 버튼이 있습니다.

### 커밋 창
**Tools → Git → 커밋 창**

파일 고르기
- 커밋하지 않은 변경을 파일별로 보여 줍니다. **체크한 파일만** 로컬 커밋합니다. 짝 `.meta`는 함께 체크됩니다.
- PC·유저마다 다른 설정 파일(`UserSettings/`, `ProjectSettings/Packages/`, `ProjectSettings/GitSyncSettings.json` 등)은 `[제외]`로 표시됩니다. 처음 열 때·새로 감지할 때·**모두 선택**에서 자동으로 체크되지 않으며, 필요하면 직접 클릭해 커밋합니다. 경로는 설정에서 바꿀 수 있습니다.
- `git rm --cached`로 추적만 해제한 파일은 **해제**로 한 줄에 보입니다. 체크하면 파일은 PC에 남긴 채 Git에서만 빼는 커밋이 됩니다(`.gitignore`에 걸린 파일도 됨).

커밋을 막거나 확인하는 경우
- 플레이 모드, 컴파일 중, 콘솔 에러가 있으면 커밋 버튼이 꺼집니다.
- 저장하지 않은 씬이 있으면 저장할지 묻습니다.
- `Packages/manifest.json`에서 패키지가 빠지는 변경이 있으면 경고하고, 그 파일을 커밋할 때 한 번 더 확인합니다.
- 원격이 앞서 있으면(다른 PC·사람이 먼저 올림) 경고합니다.
- 커밋 도중 실패하면 스테이징을 실행 전 상태로 되돌립니다.

푸시
- 아래쪽에 카운트 상태와 올릴 커밋 수가 보입니다.
- **카운트 시작**, **푸시…**(미리보기를 확인한 뒤 푸시) 버튼이 있습니다.

### 설정
**Tools → Git → 설정** (또는 Edit → Project Settings → Git Sync)

#### 팀원이 보는 세 칸 (개발자가 아니어도)
| 칸 | 무엇인가 | 무엇을 적나 (예: MyGame) |
|---|---|---|
| 저장소 폴더 | 작업 파일이 들어 있는 Git 폴더. GitHub Desktop의 File → Clone repository로 받은 폴더(예: `C:\GitHub\MyGame`) | **비워 둡니다.** 이 Unity 프로젝트가 들어 있는 폴더를 자동으로 찾습니다. |
| 원격 이름 | GitHub에 있는 팀 저장소(예: `https://github.com/<팀 계정>/MyGame`)를 이 PC에서 부르는 별명 | **`origin`.** GitHub Desktop으로 Clone하면 항상 origin입니다. |
| 브랜치 | 팀이 함께 작업을 올리는 줄기 이름 | 팀이 정한 이름(보통 **`main`**). GitHub Desktop 위쪽 **Current branch**가 이 이름이어야 푸시됩니다. |

`이 PC에서 확인` 줄에 ✖가 보이면:
| 안내 | 할 일 |
|---|---|
| Git 폴더 안에 있지 않습니다 | GitHub Desktop에서 팀 저장소를 Clone하고, 받은 폴더 안의 Unity 프로젝트를 Unity Hub에서 엽니다. |
| 원격이 없습니다 | 원격 이름 칸에 `origin`을 적고 **저장**합니다. |
| Current branch가 다릅니다 | GitHub Desktop 위쪽 Current branch에서 `main`(팀이 정한 브랜치)을 고릅니다. |

#### 전체 항목
위쪽 '프로젝트 공용 설정'은 `ProjectSettings/GitSyncSettings.json`에 저장되며 **Git에 올려 팀이 같이 씁니다.** 아래쪽은 PC마다 따로입니다(EditorPrefs).

| 항목 | 저장 위치 | 기본값 | 설명 |
|---|---|---|---|
| 저장소 폴더 | 공용 | 비움 | 비우면 프로젝트 폴더가 들어 있는 Git 저장소. 프로젝트가 저장소의 하위 폴더여도 됩니다. |
| 원격 이름 / 브랜치 | 공용 | `origin` / `main` | 푸시할 곳. 지금 브랜치가 이 브랜치일 때만 푸시합니다. |
| 푸시 주기 (분) | 공용 | 60 | 카운트 시작부터 이 시간이 지나면 푸시 차례 |
| 묶음 커밋 만들기 | 공용 | 켬 | 마지막 푸시 뒤의 개별 커밋을 묶음 커밋 1개로 합쳐 그것만 올림. 끄면 개별 커밋을 그대로 올림 ([동작 방식](#4-커밋과-푸시가-동작하는-방식)) |
| 작업 기록 폴더 | 공용 | 비움(끔) | `entryNNN.md`가 있는 폴더(프로젝트 기준). 새 항목의 제목을 작업 내용으로 씀 |
| 작업 내용 자동 요약 | 공용 | 끔 | `claude`로 바꾸면 바뀐 내용을 claude가 요약 |
| Python 경로 | PC별 | 비움(자동) | 비우면 3.8 이상을 차례로 찾음 (Windows: `python` → `py` → `python3`, macOS·Linux: `python3` → `python` → Homebrew 경로) |
| claude 경로 | PC별 | 비움(PATH) | Unity가 PATH를 못 볼 때 `claude.exe` 전체 경로 |
| 자동 체크 제외 경로 | PC별 | `UserSettings/`, `ProjectSettings/Packages/`, `ProjectSettings/GitSyncSettings.json` | 커밋 창에서 자동으로 체크하지 않을 경로(한 줄에 하나) |

### 새 버전 알림
Git 주소로 설치한 경우에만 동작합니다. 로컬 폴더(`file:`)로 설치했으면 확인하지 않습니다.

- 에디터를 켤 때 하루 한 번 저장소의 `vX.Y.Z` 태그를 확인합니다. 새 버전이 있으면 콘솔에 남기고 알림 창을 띄웁니다.
- 알림 창 버튼:
  - **업데이트**: Package Manager로 `주소#새 태그`를 설치합니다. `Packages/manifest.json`이 바뀌므로 커밋해서 팀과 버전을 맞춥니다.
  - **이 버전 건너뛰기**: 그 버전은 다시 알리지 않습니다.
  - **나중에**: 다음 확인 때 다시 알립니다.
- 언제든 **Tools → Git → 업데이트 확인** 또는 패널 툴바의 **업데이트 확인**으로 직접 확인할 수 있습니다.

## 4. 커밋과 푸시가 동작하는 방식

### 작업 내용(커밋 설명)을 정하는 순서
1. 작업 기록 폴더에 저장소에 아직 없는 새 항목이 있으면 그 제목 (`- 제목`으로 들어감)
   - 항목 첫 줄 `### 334. 제목 (2026-11-11 PM 5:24)`에서 번호·날짜 괄호를 빼고 제목만 씁니다.
2. 커밋 창(또는 `--title`)에 직접 쓴 제목
3. 자동 요약이 켜져 있으면 `claude -p`의 한두 줄 요약 (30초 안에 못 받거나 실패하면 4로)
4. 파일 종류·이름 요약 (스크립트·씬·프리팹·이미지·기타)

### 푸시
- **묶음 커밋**: 마지막 푸시 뒤의 개별 커밋을 하나로 합칩니다. 작업 내용과 파일 수는 합산됩니다. 푸시 뒤에는 원격과 로컬 브랜치 모두 묶음 커밋만 남고, 개별 커밋은 [묶기 전 백업](#묶기-전-백업)에만 남습니다.
- **순서**: 묶음 커밋을 먼저 원격에 올리고, **성공한 뒤에만** 로컬 브랜치를 그 커밋으로 옮깁니다(`git reset --soft`).
  - 푸시가 실패하면 로컬은 그대로입니다.
  - 커밋하지 않은 변경은 어느 경우에도 건드리지 않습니다.
  - 푸시 응답이 오류·시간 초과(10분)여도, 원격을 다시 확인해 실제로 올라가 있으면 성공으로 처리합니다.
- **첫 푸시**: 원격에 브랜치가 아직 없으면 묶지 않고 기존 기록을 그대로 올립니다(이 도구로 만들지 않은 지난 커밋까지 합쳐 버리지 않도록). 다음 푸시부터 묶습니다.
- **강제 푸시는 하지 않습니다.**

### 묶기 전 백업
- 로컬 브랜치를 묶음 커밋으로 옮기기 전에, 묶기 전 개별 커밋을 `refs/gitsync/backups/날짜-시각`에 남깁니다(최근 30개).
- 브랜치 목록·GitHub Desktop·원격에는 나타나지 않습니다.
- 개별 커밋 기록이 필요하면 명령줄의 `--backups`로 보고 `--restore-backup 이름`으로 브랜치로 꺼냅니다. 꺼낸 브랜치는 올리지 마세요.
- 이미 원격에 올라간 묶음 커밋을 되돌리려면 강제 푸시가 필요하므로, 되돌리기 대신 꺼내 보기만 합니다.

## 5. 멈추는 경우와 할 일
멈추면 원인 안내와 git 오류를 함께 보여 줍니다.

| 멈추는 경우 | 커밋 | 푸시 | 할 일 |
|---|:---:|:---:|---|
| 브랜치가 아닌 커밋을 보고 있음(detached HEAD) | ● | ● | GitHub Desktop 위쪽 Current branch에서 팀 브랜치를 고릅니다. |
| 지금 브랜치가 설정의 브랜치가 아님 | | ● | 위와 같습니다. 로컬 커밋은 할 수 있습니다. |
| 병합·리베이스·체리픽·bisect 등이 끝나지 않음 | ● | ● | 마무리하거나 취소한 뒤 다시 합니다. |
| 고르지 않은 파일·변경이 이미 스테이징돼 있음 | ● | ● | 스테이징을 비운 뒤 다시 합니다. |
| 커밋할 파일·올릴 커밋이 없음 | ● | ● | — |
| 원격에 이 PC에 없는 커밋이 있음 | | ● | GitHub Desktop에서 먼저 **Pull**로 받아 합친 뒤 푸시합니다. |
| 원격 확인 실패·시간 초과(120초) | | ● | 안내를 따릅니다. GitHub 로그인 창이 떠 있을 수 있습니다. |
| 푸시 실패·시간 초과(10분) | | ● | 안내를 따릅니다. 로컬은 그대로입니다. |

원격에는 올라갔는데 로컬 브랜치를 옮기지 못하면, 직접 실행할 `git reset --soft <커밋>` 명령을 알려 줍니다.

## 6. 명령줄 (Claude Code 등)
에디터를 한 번 켜면 도구가 `Library/GitSync/Tools/`에 복사됩니다. 프로젝트 폴더에서 실행합니다.
다른 폴더에서 실행할 때는 `--project <Unity 프로젝트 폴더>`를 붙입니다.

커밋
```
python Library/GitSync/Tools/gitsync_commit.py --dry-run                 # 바뀐 파일과 커밋 설명 미리보기
python Library/GitSync/Tools/gitsync_commit.py --files-from 목록.txt      # 목록(저장소 기준 경로, 한 줄에 하나)의 파일만 커밋
python Library/GitSync/Tools/gitsync_commit.py --title "로그인 화면 고치기" # 작업 내용 직접 쓰기
python Library/GitSync/Tools/gitsync_commit.py                           # 바뀐 파일 전체 커밋
```

푸시
```
python Library/GitSync/Tools/gitsync_push.py --start      # 작업 시작 때 (카운트가 멈춰 있으면 지금부터)
python Library/GitSync/Tools/gitsync_push.py --status     # 지난 시간·푸시 차례
python Library/GitSync/Tools/gitsync_push.py --dry-run    # 묶음 커밋 설명 미리보기
python Library/GitSync/Tools/gitsync_push.py              # 개별 커밋을 묶음 1개로 합쳐 푸시 → 카운트 멈춤
```

묶기 전 백업
```
python Library/GitSync/Tools/gitsync_push.py --backups                          # 백업(개별 커밋) 목록
python Library/GitSync/Tools/gitsync_push.py --restore-backup 20261120-131606   # 백업을 gitsync-backup-… 브랜치로 꺼냄
```

## 7. 주의
- `Library/`가 Git에서 빠져 있어야 합니다(Unity 기본 `.gitignore`). 카운트 상태와 도구 복사본이 거기 있습니다.
- 설정의 **저장소 폴더**는 Git으로 팀과 공유됩니다. 이 PC의 절대 경로를 넣으면 다른 PC에서 저장소를 잘못 찾으므로 비워 두세요. 설정 화면·패널·커밋 때 경고합니다.
- 명령줄 도구도 커밋할 때 패키지 빠짐·저장소 폴더 절대 경로를 `주의:`로 알려 줍니다(멈추지는 않음). 먼저 `--dry-run`으로 확인하세요.
- 커밋 설명에 공동 작성자·AI 표시 줄을 넣지 않습니다.

## 8. 폴더 구성과 시험
```
package.json
Editor/                  커밋 창, 설정 화면, 도구 실행 (에디터 전용 어셈블리)
Tools~/                  파이썬 도구 (Unity가 가져오지 않는 폴더)
  gitsync_commit.py      로컬 커밋
  gitsync_push.py        시간 규칙 + 묶음 커밋 푸시
  gitsync_common.py      설정·형식 공용
Tests~/                  시험 (Unity가 가져오지 않는 폴더)
  test_gitsync.py        임시 원격·예시 프로젝트 MyGame으로 커밋·푸시 도구 시험
Documentation~/          운영 가이드
```

시험은 패키지 폴더에서 실행합니다. 사용자의 Git 설정·로그인은 쓰지 않습니다.
```
python "Tests~/test_gitsync.py"
```
