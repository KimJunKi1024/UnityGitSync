# Git 운영 가이드

> 이 패키지가 따르는 규칙입니다. 원본은 엘라린 프로젝트의 운영 가이드(2026-11-11)이고, 경로·이름은 어느 프로젝트에서나 쓸 수 있게 바꿨습니다.
> 아래 `<도구>`는 `Library/GitSync/Tools` (Unity 에디터를 켜면 패키지의 `Tools~`가 여기로 복사됨)입니다.

## 1. 커밋
- 작업 하나가 끝나면(컴파일 오류 0, 확인 완료, 작업 기록 반영) 그 작업 파일만 로컬 커밋합니다.
  - Unity: **Tools → Git → 커밋 창**에서 파일을 골라 커밋
  - 명령줄: `python <도구>/gitsync_commit.py --files-from 목록파일` (먼저 `--dry-run`)
- 에러가 남았거나 확인하지 못한 작업, 멈추라고 한 작업은 커밋하지 않습니다.
- 커밋 설명 형식 (이 밖의 내용은 적지 않음):

```
2026-11-11 PM 5:24

작업 내용
- 334. 튜토리얼 대사에서 '튜토리얼' 표현 빼기

파일: 추가 1, 수정 2
총 작업한 내용: 3개
```

- 첫 줄(요약)은 커밋 시각 `YYYY-MM-DD AM/PM h:mm`.
- `작업 내용`은 다음 순서로 정합니다.
  1. 작업 기록 폴더(설정)에 저장소에 아직 없는 새 항목(`entryNNN.md`)이 있으면 그 제목 (`- 번호. 제목`)
  2. 커밋 창·`--title`에 직접 쓴 제목
  3. 설정에서 자동 요약을 켰으면 `claude -p`가 바뀐 내용을 보고 쓴 한두 줄 요약 (30초 안에 못 받거나 실패하면 4로)
  4. 파일 종류·이름으로 만든 요약. 예: `스크립트 2개 수정: PlayerController, UnitGenerator / 씬 Village 수정`
- `파일:`은 추가·수정·삭제(·이동) 순서, 0인 종류는 뺍니다. `총 작업한 내용`은 바뀐 파일 수의 합계입니다.
- `Co-Authored-By` 같은 공동 작성자·AI 표시 줄은 넣지 않습니다.

## 2. 푸시 주기 (기본 1시간 규칙)
- 작업을 하는 동안 **설정한 시간(기본 1시간)마다 1번** 푸시합니다.
- 시간이 됐을 때 **작업 중이면 그 작업을 끝낸 뒤** 푸시합니다.
- 시간은 푸시한 순간부터 세지 않습니다. 푸시한 뒤 **다음 작업을 시작하는 순간**부터 셉니다.
  - 예: 17:00 푸시 → 17:30에 다음 작업 시작 → 18:30이 다음 푸시 차례. 18:30에 작업 중이면 그 작업이 끝난 뒤 푸시.

## 3. 푸시 절차
1. 작업 시작 때: 커밋 창의 **카운트 시작** 또는 `python <도구>/gitsync_push.py --start` (카운트가 멈춰 있으면 지금부터 셈)
2. 작업이 끝날 때마다: 커밋 창 아래쪽 또는 `--status`로 시간이 지났는지 확인
3. 차례가 되면: 커밋 창의 **푸시…**(미리보기를 보여 주고 확인을 받음) 또는 `--dry-run`으로 확인 → `python <도구>/gitsync_push.py`
   - 묶음 커밋을 켜 두면(기본) 마지막 푸시 뒤의 개별 커밋을 작업 내용과 파일 수를 합산한 **묶음 커밋 1개로 합쳐 그것만** 올립니다.
     - 원격 기록에는 푸시마다 묶음 1개만 남고, 개별 커밋은 로컬에도 남기지 않습니다.
     - 묶음 커밋을 먼저 푸시하고, 성공한 뒤에만 로컬 브랜치를 옮깁니다. 푸시가 실패하면 로컬 개별 커밋은 그대로입니다.
     - 커밋하지 않은 작업 폴더 변경은 그대로 둡니다. 이미 원격에 올라간 지난 커밋은 건드리지 않습니다.
   - 묶음 커밋 설명은 1장의 형식과 같습니다.
   - 푸시 뒤 카운트는 멈추고, 다음 작업을 시작할 때 다시 셉니다.
- 카운트 상태는 `Library/GitSync/push_state.json`(PC마다 따로, Git에 안 올라감)에 적힙니다.

## 4. 멈추고 알리는 경우
- 원격에 이 PC에 없는 커밋이 있을 때(다른 PC·다른 사람이 먼저 푸시함): 받아서(Pull) 합친 뒤 푸시. 합치는 방법은 직접 정합니다.
- 이미 스테이징된 변경이 있을 때(따로 올려 둔 변경이 섞일 수 있음).
- 강제 푸시(`--force`)는 하지 않습니다.

## 5. 여러 PC·여러 사람이 작업할 때
- 작업 시작 전에 GitHub Desktop(또는 `git pull`)으로 다른 PC의 작업을 먼저 받습니다.
- 한 PC에서 커밋만 하고 푸시하지 않으면 다른 PC는 그 작업을 모릅니다. 푸시 주기를 지키면 차이가 그 시간 안쪽으로 유지됩니다.
