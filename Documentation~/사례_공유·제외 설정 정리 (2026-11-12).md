# 사례: 공유·제외 설정 정리 (2026-11-12)

Build The Barbell 프로젝트(Unity 6 2D)에 Git Sync(`com.teamelarin.gitsync` v1.0.1)를 쓰다가 생긴 문제와 정리 과정을 적은 기록입니다. 같은 문제를 다른 프로젝트에서 막을 때 참고합니다.

## 1. 무슨 일이 있었나

- 다른 PC에서 올린 커밋이 두 가지를 망가뜨렸습니다.
  - `ProjectSettings/GitSyncSettings.json`의 `repo`가 그 PC의 경로로 바뀜 → 이 PC에서 저장소를 잘못 찾음
  - `Packages/manifest.json`에서 Unity MCP(`com.coplaydev.unity-mcp`)가 빠짐
- 복구해서 푸시한 뒤, 재발을 막으려고 "두 PC가 같이 쓸 설정"과 "PC마다 따로 둘 설정"을 나눴습니다.

## 2. 공유하는 설정과 빼는 설정

| 구분 | 대상 | 이유 |
|---|---|---|
| 공유 | 레이어·태그(`TagManager`), 물리, 입력, 품질·그래픽, 빌드 씬 목록, 플레이어 설정·정의 기호, 패키지 목록(`manifest.json`, `packages-lock.json`) | 게임 동작이 달라짐 |
| 공유 | `ProjectSettings/GitSyncSettings.json` (단, `repo`는 항상 `""`) | 원격·브랜치 같은 공용 설정. 경로는 PC마다 다르므로 비워 두면 자동으로 찾음 |
| 제외 | `UserSettings/` | 창 배치 같은 개인 편집기 상태 |
| 제외 | `ProjectSettings/Packages/com.unity.ai.assistant/` | 도구의 PC별 상태, 게임과 무관 |
| 제외 | `ProjectSettings/Packages/com.unity.learn.iet-framework/` | 도구의 PC별 상태, 게임과 무관 |

`.gitignore` 끝에 추가한 줄:

```gitignore
# 에디터 도구의 PC별 상태 (게임과 무관, PC마다 바뀜) (2026-11-12)
/ProjectSettings/Packages/com.unity.ai.assistant/
/ProjectSettings/Packages/com.unity.learn.iet-framework/
```

이미 추적 중이던 파일은 `.gitignore`만으로 빠지지 않으므로 `git rm --cached`로 추적을 해제했습니다(파일은 PC에 남음).

## 3. 커밋 전 확인 규칙 (프로젝트 `ClaudeCode/CLAUDE.md`에 추가)

> 1.2.0부터는 도구도 같은 내용을 알려 줍니다: 커밋 창은 패키지가 빠지면 경고·확인 창을 띄우고, 설정 화면·패널·커밋 도구는 `repo`에 PC 경로가 있으면 경고합니다.

- `Packages/manifest.json`에서 패키지가 **빠지는** 변경이 있으면 멈추고 사용자에게 묻는다.
- `ProjectSettings/GitSyncSettings.json`의 `repo`에 PC 경로가 들어 있으면 `""`로 비운 뒤 커밋한다.

## 4. Git Sync 도구로 처리하지 못한 경우

- `gitsync_commit.py`는 목록에 없는 파일이 이미 스테이징되어 있으면 멈춥니다. 또 `.gitignore`에 걸린 경로는 add하지 못합니다.
- 그래서 추적 해제(삭제 2개)가 들어간 커밋은 사용자 승인을 받고 `git commit`으로 직접 했습니다. 메시지는 도구 미리보기와 같은 형식으로 맞췄습니다.

```text
2026-11-12 PM 5:02

작업 내용
- PC별 에디터 도구 설정 공유 제외 및 커밋 전 설정 확인 규칙 추가

파일: 수정 2, 삭제 2
총 작업한 내용: 1개
```

- 개선 후보: 추적 해제(`git rm --cached`)처럼 스테이징된 삭제를 도구가 목록으로 받아 처리할 수 있으면 직접 커밋이 필요 없습니다.
  - → **1.2.0에서 반영**: 추적 해제한 파일은 커밋 창에 "해제"로 보이고, 목록에 넣으면 다시 추가하지 않고 그대로 커밋합니다(`.gitignore`에 걸린 파일도 됨). 도중에 실패하면 스테이징을 실행 전 상태로 되돌립니다.

## 5. Unity가 패키지를 다시 읽으며 생긴 변경

다른 PC의 커밋을 받은 뒤 Unity를 열자 아래가 바뀌었습니다. 두 파일이 서로 맞는 상태라 커밋해서 공유했습니다(도구 `--title` 사용).

- `packages-lock.json`: `com.coplaydev.unity-mcp` 잠금 정보 추가, `com.unity.ai.assistant` `2.21.0-pre.1` → `2.21.0-pre.2`
- `manifest.json`: `com.unity.ai.assistant` 같은 버전 변경, Git Sync 줄은 줄끝 문자만 바뀜

## 6. 결과

- 로컬 커밋 2개 → `gitsync_push.py`가 묶음 커밋 1개(`caebf4e`)로 합쳐 `origin/main`에 푸시
- 푸시 뒤 작업 폴더에 남은 변경 없음

## 7. 필요한 환경

- Python 3.8 이상 (표준 라이브러리만 사용).
  - 1.2.0부터: 경로를 비워 두면 Windows에서는 `python` → `py` → `python3` → 표준 설치 위치 순서로 찾습니다. (이 사례의 v1.0.1은 설정의 Python 경로를 그대로 씀)
- 새 PC에서는 **Tools → Git → Git Sync 패널**(1.1.0~1.1.x는 **환경 확인**)에서 git·Python·도구·저장소가 모두 ✔인지 먼저 봅니다.
